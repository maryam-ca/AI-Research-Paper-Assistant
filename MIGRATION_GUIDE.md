# ScholarFlow — Move to a New Laptop (USB) & Deploy on Vercel

This guide assumes you developed ScholarFlow on laptop A and are moving the
source to laptop B (via USB stick), where you already have a Neon Postgres account.
From laptop B you will deploy to Vercel.

------------------------------------------------------------------------------
PART 0 — WHAT NOT TO COPY
------------------------------------------------------------------------------
These are machine-specific / secret and should NEVER travel on the USB stick:

  - frontend/node_modules/        (regenerated by npm install)
  - frontend/api/.venv/           (regenerated by python -m venv)
  - .blobs/                       (local upload cache; not used on Vercel)
  - frontend/.env.local           (SECRETS — recreate on laptop B)
  - frontend/api/.env            (SECRETS — recreate on laptop B)

Only copy the SOURCE files (everything else).

------------------------------------------------------------------------------
PART 1 — COPY FROM LAPTOP A TO THE USB STICK
------------------------------------------------------------------------------
1. Open a terminal on laptop A in the project root:
       D:\Code Cortex\03_Projects\Current\15-AI-researchh-paper-assistant

2. Make a clean source copy (excludes the heavy/machine-specific folders):
       robocopy . "E:\ScholarFlow" /E /XD node_modules .venv .blobs /XF .env.local .env
   (replace E:\ with your USB drive letter)

   Or simply drag the project folder to the USB, then DELETE these from the
   copy before ejecting:
       frontend\node_modules
       frontend\api\.venv
       .blobs
       frontend\.env.local
       frontend\api\.env

3. Safely eject the USB stick.

------------------------------------------------------------------------------
PART 2 — RESTORE ON LAPTOP B
------------------------------------------------------------------------------
1. Plug in the USB and copy the ScholarFlow folder to laptop B
   (e.g. C:\Projects\ScholarFlow).

2. Install required runtimes on laptop B:
   - Node.js 20+  (https://nodejs.org)
   - Python 3.11+ (https://python.org)
   - (Git optional — only needed if you want to push to GitHub)

3. Recreate the backend virtualenv and install deps:
       cd frontend\api
       python -m venv .venv
       .venv\Scripts\activate
       pip install -r requirements.txt

4. Recreate the FRONTEND deps:
       cd ..\
       npm install

------------------------------------------------------------------------------
PART 3 — CREATE THE SECRETS / ENV FILES ON LAPTOP B
------------------------------------------------------------------------------
Create  frontend\.env.local  with:

   VITE_API_URL=http://localhost:8000/api

Create  frontend\api\.env  with (see Part 4 for the values):

   DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST/neondb?sslmode=require
   GEMINI_API_KEY=your_google_gemini_key
   BLOB_READ_WRITE_TOKEN=your_vercel_blob_token

NEVER put real secrets on the USB stick or in git.

------------------------------------------------------------------------------
PART 4 — NEON DATABASE (you already have an account on laptop B)
------------------------------------------------------------------------------
1. Log into Neon, create a new project (or use an existing one).
2. Copy the connection string from the Neon dashboard
   (it looks like:  postgresql://user:pass@ep-xxx-pooler.region.aws.neon.tech/neondb?sslmode=require).
3. Paste it into  frontend\api\.env  as  DATABASE_URL  (keep the
   postgresql+psycopg://  driver prefix if you keep psycopg v3).
4. Run the schema + migrations ONCE so tables exist:
       cd frontend\api
       python init_db.py
       python migrate_tier1.py
       python migrate_tier2.py
       python migrate_tier3.py
   (init_db.py + the three migrate scripts are idempotent / re-runnable.)

Note: on laptop B you only need Neon for the final deploy. To run locally you
can also create a local Postgres, but Neon is simplest since it is already there
and is what Vercel will use.

------------------------------------------------------------------------------
PART 5 — GET A GEMINI KEY + VERCEL BLOB TOKEN
------------------------------------------------------------------------------
- GEMINI_API_KEY:  https://aistudio.google.com/apikey  (free tier works).
- BLOB_READ_WRITE_TOKEN: go to Vercel dashboard -> Storage -> create a Blob
  store -> copy the read-write token. This is REQUIRED for file/thumbnail
  uploads on Vercel (the local .blobs fallback does not work in serverless).

------------------------------------------------------------------------------
PART 6 — TEST LOCALLY ON LAPTOP B (optional but recommended)
------------------------------------------------------------------------------
Terminal 1 (backend):
   cd frontend\api
   .venv\Scripts\activate
   uvicorn main:app --reload --port 8000

Terminal 2 (frontend):
   cd frontend
   npm run dev
   # open http://localhost:5173

------------------------------------------------------------------------------
PART 7 — DEPLOY TO VERCEL (from laptop B)
------------------------------------------------------------------------------
1. Push the project to GitHub (do NOT commit .env.local / .env / node_modules /
   .venv — they are gitignored). If you have no git repo yet:
       git init
       git add -A
       git commit -m "ScholarFlow"
       git remote add origin <your-github-repo>
       git push -u origin main

2. In Vercel: Import the GitHub repo and set **Root Directory = frontend/**.

3. Project Settings -> Environment Variables, add:
       DATABASE_URL        = <Neon string from Part 4>
       GEMINI_API_KEY      = <from Part 5>
       BLOB_READ_WRITE_TOKEN = <from Part 5>
       VITE_API_URL        = https://<your-vercel-domain>/api

4. Deploy. The  frontend/vercel.json  file routes  /api/*  to the Python
   serverless function automatically.

5. After the first successful deploy, run the migrations against Neon from
   laptop B (so the production DB has all tables):
       cd frontend\api
       $env:DATABASE_URL="<neon-string>"
       python migrate_tier1.py
       python migrate_tier2.py
       python migrate_tier3.py

6. Open the deployed URL. Upload a paper to confirm Blob + DB + Gemini all work.

------------------------------------------------------------------------------
PART 8 — CHROME EXTENSION (only if you use it)
------------------------------------------------------------------------------
The  extension/  folder defaults to http://localhost:8000/api. After deploy,
open  extension/popup.js  (or the popup UI) and set the API base to
https://<your-vercel-domain>/api  before loading it in Chrome.
